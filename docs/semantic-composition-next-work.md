# 集合计算、日历偏移与对话指代：下一轮工作分配

诊断基线：`b0e145c`，2026-09-07。本文是下一轮工作票；本轮仅检查源码与既有报告，没有修改生产代码或重新运行 LLM 基准。

## 已确认的结构性缺口

1. **集合结果被当成单值歧义。** `operator_registry.py` 将 `date_difference` 声明为 scalar；`SemanticFactExecutor.execute` 据输入形状选择 `expect_many`，后续 `_operate` 对 scalar 调用 `_singular`。当前 `select(property)` 也要求单个对象。因此“每位成员的年龄”缺少保留实体归属的逐项计算表达，不是补充年龄知识能解决的。
2. **指代所需的历史被截断两次。** `SemanticFactPlanner.plan` 从传入 messages 中只抽取 `latest_user_message`；`OllamaService.plan_semantic_fact` 再次只转发最新用户消息。即使调用方提供前文，解释器仍看不到“匡德伦几岁了”。`AgentRequestContext` 也没有会话指代绑定。
3. **指定周年日期无法表达。** `_annual_occurrence` 从当前年份寻找下一个相同月日，没有第 N 周年参数；现有 IR 没有日历偏移量。“十岁生日”需要出生日期加十个日历年，不能用下一次生日替代。
4. **“其他”缺少明确的集合排除表达。** 现有 `other` 是二元比较操作数，不是集合排除；普通集合过滤也没有可用的上下文实体排除接口。排除说话人还是前文焦点必须先由解释器表达，不能在结果列表中猜测性删除。

以上是源码确认的能力边界。用户这两次请求的原始模型输出及服务端 trace 尚未取得，不能断言实际失败时模型输出了哪一个计划。

## Codex 工作票：扩展最小可组合语义契约并实现核心链路

**目标：** 同时支持集合上的逐项属性计算、指定日历周年和有依据的跨轮指代；不增加年龄列表、十岁生日等专用问句处理器。

### C1：集合形状、逐项投影与排除

- 先定义有类型的最小 IR 扩展，区分单个实体、实体集合和带实体归属的结果行。可以采用受限 `map/project` 组合，无需引入通用脚本或无界表达式语言。
- 显式区分用户要求的集合与意外产生的多个候选。单值操作仍应对真正的多候选报歧义，不能全局关闭 `_singular`。
- 支持通用引用集合差，例如成员集合减去已解析的 `self` 或前文引用。不要将“其他”写成固定排除 self 的规则；根据上下文解释，无唯一含义时澄清。
- 复用 `date_difference(..., years)`，逐行保留实体、数值、单位、证据和缺失状态；缺少一个人的出生日期不应丢掉其他人的有效结果。
- Renderer 根据结构化结果形状呈现多人结果，不再要求用户选一个人。

### C2：通用日历偏移

- 定义类似 `date_add(date, amount, unit)` 的通用原语，可用于实体属性和关系属性；明确日历年/月、闰日、月底和时区政策。
- 十岁生日表达为 `date_add(birth_date, 10, years)`；婚姻第十周年同样由关系 `start_date` 加十年得到。不得计算“当前年龄距离十岁还差多少”再猜未来生日。
- 指定周年即使已过去也返回该日期；“下一次生日”继续由 `annual_occurrence` 负责。使用过去周年和远期周年测试，避免两个操作偶然返回同一天掩盖错误。

### C3：会话指代契约与接线

- 明确从 API 到解释器的会话信息流，同时处理两处历史截断。仅将裸历史塞进 prompt 不算完成。
- LLM 解释话语中的指代关系，输出诸如“前一轮已解析主题”的语义引用；可信上下文维护其实体/集合绑定，解析器再接入权威图。模型不生成 canonical ID，不从旧回复中的年龄数值推算新答案。
- 会话状态必须限定在正确的会话和说话人范围；明确保存、失效、主题切换及无状态调用的行为。助手回复文本不是权威事实来源。
- 唯一明确前文可以绑定；多人候选、缺失前文、跨会话或指代冲突应给出有针对性的澄清，不猜最近一个男性。

**顺序与交付：** 先冻结 C1–C3 的接口、结果形状和错误语义，交给 Grok 编写独立验收；实现顺序 C1 → C2 → C3，每步独立提交候选变更。Codex 负责核心架构、IR/验证器/解析器/执行器/呈现/会话接线及必要本地单元测试。最后审查 Grok 的基准失败分类，不用反复调例句换取分数。

## Grok 工作票：独立基线、泛化回归与生产 GPU 验证

### G1：现在可开始，先补观测和测试规格

- 对用户提供的失败链取得可复核 trace：最新输入、实际传入的前文、模型原始计划、验证结果、解析候选、执行状态和呈现结果。记录部署 revision，区分没有发送历史与服务端丢弃历史。
- 设计稳定 case ID 的虚构家庭数据与多轮测试输入；先记录语义期望，待 Codex 冻结 IR 后填写精确计划。不得把基准句子写入解释器例子。
- 拆开四组对照：单人/多人年龄；全体/排除自己/排除前文对象；显式姓名/代词；下一次生日/指定周年。包括重名、零成员、缺失日期、主题切换、两名同性交谈对象、不同会话及不同说话人。
- 增加跨域组合：每段居住关系的时长、关系的第 N 周年、不同人名/日期/周年数字，以及中英文未见改写。单轮显式姓名成功不能代替多轮指代成功。

### G2：接口冻结后扩展 harness 并跑验收

- 负责 benchmark harness、虚构 fixtures、独立集成回归及报告；不自行修改核心语义规则或放宽等价判定。
- 多轮 harness 必须保留服务实际产生的状态与前轮结果，经正常服务入口逐轮执行，不可把第二轮重写成完整姓名来规避指代。
- 分别评分计划、指代绑定、成员集合（含排除）、每行数值/单位/状态以及呈现；把合法澄清与错误拒绝区分开。答案不得仅凭 `found` 评分。
- **软件单元/回归测试在本地；需要真实 LLM 的测试全部在生产 GPU 隔离目录。** 使用虚构数据为主，真实家庭只做获授权的只读核对；记录 package/data/schema/model/contract fingerprints、冻结时钟和请求设置。
- 新探针先 warmup 1、repeat 5，再跑既有 119 题、24 条年龄/筛选、16 条日期间隔。记录全部分母、P50/P95、逐项失败及与同配置基线差异。旧 119 题没有答案期望，不能称为答案准确率。
- 保留大 JSON 在隔离目录，仓库只放 summary 和报告；不部署线上应用。发现核心错误时提交最小失败 IR/trace 给 Codex。

## 验收门槛

- 本地确定性契约测试全部通过；单值歧义保护、属性所有权和身份/存储隔离不回退。
- 每种新能力必须展示跨实体、跨属性所有者、跨措辞及边界条件的组合泛化，不能只有用户原句通过。
- 两条用户失败链必须走正常服务路径通过：多人年龄返回逐人结果；姓名年龄查询之后的代词十岁生日追问绑定正确对象并返回指定周年。
- 真实 LLM 的失败必须如实保留；既有失败与新增回退分别列出。上一轮 113/119 是历史参照，不能代替本轮同环境基线。
- 本票完成诊断与分工；实现、基准和部署分别汇报，不把计划当作已执行结果。
