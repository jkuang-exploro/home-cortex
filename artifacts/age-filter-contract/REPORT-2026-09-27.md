# Numeric-age collection filter follow-up

Date: 2026-09-27 PDT. The reported `55岁以上` answer showed `年龄 < 55岁`
because the interpreter emitted a completed-years comparison on `birth_date`
with `lt`; the executor followed that plan. This was observed repeatedly on an
isolated synthetic fixture with the production Ollama model. A generic reminder
and paired examples using the old transform shape did not reliably correct it.

The current source declares filter-only `age_years` in the ontology, sourced
from `birth_date` and computed as completed calendar years at Household now.
The model compares that numeric semantic value directly. Schema validation,
collection execution, traversal execution, and rendering all use the declared
computed filter; no utterance text is inspected downstream and no threshold
specific to 55 was coded. Old transformed-date IR remains executable
internally for compatibility but is absent from the collection planner-output
schema. The renderer now displays `年龄 ≥ 55岁` for the corresponding request.

Local deterministic tests cover thresholds 18, 46, 55, and 70, birthday
boundaries through the existing date-difference tests, traversal composition,
invalid thresholds, and rendering. The full suite passed **1004 tests**.

On the production GPU host, the isolated current-source planner emitted
`age_years gte 55` or `age_years lt 55` for all **16/16** focused Chinese and
English 55-year prompts (two repetitions each). Five of six additional
varied-threshold prompts (35, 40, 56, 57, 70) used the expected numeric
comparison. The sixth, explicit `18岁以上`, mapped to the separate declared
`adult` predicate. That predicate can use household role and therefore is not
proven equivalent to an age filter on every graph. This edge remains open;
the 55-year repair is not a claim of universal interpretation accuracy.

The isolated candidate's `hc-bench standard` run scored 108/119 planner plans,
21/21 mutation classifications, 11/14 mutation payloads, 3/5 previews,
8/9 commits, 8/8 rejections, and 7/7 multi-intent turns. Both absolute safety
gates passed. See the [summary](2026-09-27-standard-summary.json) and
[provenance](2026-09-27-standard-run.json). This was one candidate run on a
fixed synthetic fixture, without a same-day paired deployed-code baseline.
The code was not deployed and the live household database was not read.
